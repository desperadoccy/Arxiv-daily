See like a Robot: Robot-Centric Pointmaps for Vision-Language-Action Models

作者: Byungkun Lee (KAIST AI); Dongyoon Hwang (KAIST AI); Dongjin Kim (KAIST AI); Hojoon Lee (Holiday Robotics); Minho Park (KAIST AI); Jaegul Choo (KAIST AI)

方向: VLA | 标签: VLA

简述: 点图对齐视角与机器人动作坐标

筛选理由: 抓住VLA坐标失配痛点，方法简单且泛化有效

Deep Review

一句话判断

这篇论文最值得关注的是：它把“观察在相机系、动作在机器人系”的 VLA 坐标失配，转化为一个几乎不改 backbone 的输入表示问题，并用 robot-centric pointmap 在模拟与真机上给出较扎实的收益；值得精读，尤其适合关注 VLA 几何表示与视角鲁棒性的读者。

核心问题与动机

论文要解决的是 VLA 中一个很基础但常被忽视的问题：模型通常看的是 RGB 或深度图这类相机坐标系观测，但输出动作却定义在机器人自身 3D 坐标系中。固定视角下，这种失配还能被“记忆映射”掩盖；但在大规模数据汇集、多机构多机位采集的场景里，训练数据跨视角差异显著，策略必须学习“不同视角观测如何对应到同一机器人动作”，泛化难度会明显上升。

现有方法的不足主要有三类。第一类给模型额外喂相机位姿/Plücker ray/重参数化动作，但视觉输入本身仍是 camera-view 图像，失配并未真正消除。第二类靠视角合成或 canonicalization，引入生成模型，远离训练视角时可靠性受限。第三类用 point cloud 等 3D 表示，虽然更几何一致，但破坏了预训练 2D VLA 依赖的致密 H×W 网格，也往往需要独立 3D 编码器。论文的动机很明确：要一种既提供机器人系的度量 3D 几何，又能保持图像结构、方便接到现有 VLA 上的输入表示。

方法拆解

整体 pipeline 很简单：输入是 RGB-D、相机内外参以及当前末端执行器位姿；输出仍是原 VLA 的动作。核心是先把每个像素通过深度和内参 lifting 到相机系 3D 点，再用外参变换到机器人 base frame，得到每像素存一个 XYZ 的 robot-centric pointmap。在此基础上，作者进一步把点图以当前 end-effector 位置为原点重心化，得到 end-effector-centered pointmap，使观测几何与动作空间共享原点。

模型侧几乎不改 VLA 主干。作者为 pointmap 使用一个与 RGB encoder 同构的独立视觉塔，且用 RGB encoder 权重初始化；随后将 pointmap token 与对应 RGB token 逐元素相加，替代原始 RGB visual tokens 输入 VLA。这个设计的关键不在复杂建模，而在：1）保留像素级空间对应，2）不引入额外 token 序列，3）不需要点云专用 encoder / voxelization / 每步渲染生成模块。训练与推理上，论文表述为在预训练 VLA 上 fine-tune；更细的优化细节在附录给出。

创新点含金量

第一，把坐标失配问题显式重写为输入表示问题，并提出 robot-centric pointmap。它针对的是 VLA 中“视觉在相机系、动作在机器人系”的核心不一致，属于实质性但概念简洁的创新；思想很可迁移，尤其适用于带标定的 manipulation 场景。

第二，点图而非点云的表示选择。本质上不是全新几何表示，而是把已有 pointmap 引入预训练 VLA，并强调“保留 H×W 图像网格”对复用 2D backbone 的价值。这更像高质量方法设计创新，工程成分较强，但论证比较完整，迁移性高。

第三，末端执行器中心化。它针对绝对工作空间坐标不利于共享局部操作几何的问题，把目标位置改写为相对 gripper 的位移。这个点并非全新，但在该框架下证实其对视角鲁棒性有帮助，属于小而有效的表示改进，很容易迁移到其他 3D policy。

实验证据

证据分三层。第一层是设计消融，质量较高：在 RoboCasa 上，RGB→RGB+Plücker→RGB+Plücker+Depth→RGB+Pointmap 的对比表明，仅给相机信息和深度不如预先计算机器人系几何；其中 pointmap 比 “Plücker+Depth” 高 3.1 个 success rate 点，较好支撑“几何预计算有益”。第二层是表示与融合选择：pointmap+add 明显优于 pointmap+concat，也优于两个点云基线，支持“保留图像网格 + 元素加和融合”这一设计。第三层是 origin 选择：end-effector centering 在固定/随机视角下都优于 base-centered，且随机视角下退化更小。

主结果方面，在 RoboCasa 24 任务上，π0.5 从 55.3 提升到 62.9，SmolVLA 从 37.2 提升到 41.4；且超过文中复现的 camera-aware 与 3D-augmented baselines。真机上，在 Franka 四任务 seen camera 下，π0.5+pointmap 比 RGB-only 高 5.0；unseen camera 下优势扩大到 11.7，且退化更小。这一部分较有说服力，尤其真机“机位未见”结果与论文动机高度一致。

但证据也有边界。多数 baseline 是作者自行复现，论文虽说明官方代码不可得，但这会削弱横向比较的绝对公正性。另一个不足是，point cloud 对比只采用单一采样预算；论文自己也承认更大预算可能缩小差距。因此“pointmap 优于点云”目前更像在当前设置下成立，而非彻底定论。

局限与风险

首先，方法依赖准确标定：训练和测试都需要相机内外参，真实部署若标定漂移、机械臂基座变化或传感器同步不稳，pointmap 质量会直接受损。这个风险论文明确承认。

其次，实验主要覆盖的是相机外参变化，对“相机数量变化、视场变化、严重遮挡、缺失深度”等情况未充分验证。论文未明确说明这些场景下的表现。

第三，方法默认能获得 RGB-D；因此对仅 RGB 的互联网式大规模数据或深度质量差的廉价硬件，适用性有限。若深度噪声大，推断：pointmap 的几何优势可能被削弱。

第四，论文没有系统分析 pointmap 与不同 action expert、不同预训练 recipe 的交互，因而其增益有多少来自表示本身、多少来自与特定 backbone 的适配，仍未完全厘清。

与我方向的关系

对 VLA / embodied AI 很相关。它给了一个值得借鉴的原则：当动作定义在某个物理坐标系中时，最好在输入侧就把观测几何对齐到该坐标系，而不是把跨坐标推理负担全部留给 transformer。这个思路对多视角数据汇集、跨实验室数据整合、机器人基础模型训练都很有启发。

对 multimodal safety/robustness，它提供的是“几何一致性提升鲁棒性”的证据：面对 unseen camera placement，性能退化更小。后续可借鉴到安全研究中，考察坐标对齐是否降低视角扰动、误检目标、手眼偏置带来的危险动作。若你做 world-grounded VLA 或 cross-view robustness，这篇很值得参考；若你关注无标定开放环境，则相关性中等。

DeepBias: Adaptive In-depth Probing of Social Biases in LVLMs

作者: Anqi Li; Jie Zhang; Zhongqi Wang; Songkai Xue; Jiahao Wang; Shiguang Shan; Xilin Chen

方向: MM | 标签: LLM-SAFETY

简述: 自适应挖掘LVLM社会偏见

筛选理由: 方法新颖，偏见测评从静态转向自适应，实用性强

Deep Review

一句话判断

这篇论文最值得关注的是把 LVLM 社会偏见评测从“静态单轮基准”改成“分布自适应生成 + 实例级多轮深挖” 的闭环范式；如果你关心多模态 safety/robustness 评测方法而不只是刷 benchmark，值得精读。

核心问题与动机

论文要解决的是：现有 LVLM 偏见评测大多基于固定图文样本、单轮问答，容易只测到“表层安全”，却测不到经过对齐后仍潜藏的更深层社会偏见。作者指出三类关键缺陷：静态公开基准容易泄漏和被适配；单轮问题无法根据模型响应继续追问，难以挖出隐性偏见；固定测试集也无法对准某个目标模型的真实脆弱点。

因此，论文提出“dynamic in-depth probing”：既要在分布层面让测试样本越来越贴近目标模型弱点，也要在实例层面围绕同一图文样本进行多轮追问，逐步把原本会被模型用“Cannot determine”挡住的问题，改写成更具情境性、比较性和诱导性的问法，从而暴露偏见。

方法拆解

整体 pipeline 是一个 “generation-evolution-probing” 闭环。输入起点是从 BBQ 里筛出的 Age/Race/Gender 文本偏见问题，再通过 SDXL 渲染成多张只改变目标人口属性、其余条件尽量一致的图片，构成初始多模态种子集 VLBBQ。每个样本本质上是三分类题：Yes / No / Cannot determine，其中在作者定义下，正确答案永远是 abstention；若模型在证据不足时给出 Yes/No，就记为 bias。

第一层是 ProposerAgent：它基于构造约束和少量示例，持续生成新候选图文样本；随后用目标 LVLM 的反馈形成偏好对。如果某个候选样本对应的多张图中，至少有一张触发了偏见回答，则该候选记为正偏好，否则记为负偏好。作者用 DPO + LoRA 更新 ProposerAgent，提高其生成“更容易击中该模型偏见漏洞”的样本概率。这里的关键不是公式本身，而是把评测数据生成视为可被 preference optimization 驱动的过程。

第二层是 DiggerAgent：它不重新造数据，而是对单个候选样本做多轮改写追问。其技能库分成两类：若上一轮还没暴露偏见，就用 contextualizing、behavior deciding、cognitive attributing 等“改写/引出”技能；若已经出现偏见，则用 contrasting、scenario escalating、attribute refining 等“加深/放大”技能。每一轮都条件化于此前问答历史，因此它不是固定模板攻击，而是实例自适应 probing。最终作者还基于 5 个 anchor LVLM 的集体反馈构建了 DeepBiasBench。

创新点含金量

第一，把偏见评测做成闭环自适应优化问题。它针对的是静态 benchmark 无法持续贴近模型漏洞的不足，属于有明确方法论意义的实质创新，而不只是“多加点测试样本”。这一思路可迁移到 hallucination、refusal consistency、视觉安全等其他评测方向。

第二，分布级适配与实例级深挖的解耦。Proposer 管分布，Digger 管单样本多轮追问，这个设计很清晰，也解释了为何仅靠 prompt attack 或仅靠 dataset expansion 都不够。这个更像“强方法组合”，但组合关系本身是经过问题结构设计的，迁移性较强。

第三，将 DPO 用于评测数据进化而非模型对齐。这点新意不错：偏好信号不是来自人类喜欢什么回答，而是来自“哪些测试数据更能触发模型偏见”。这属于方法迁移型创新，技术不新，但用途新且合理。

第四，benchmark 构建时采用 anchor ensemble，用多数投票挑选跨架构共享脆弱点，而不是为单一模型过拟合。这个是偏工程化但很关键的 benchmark 设计选择，具有较强可复用性。

实验证据

实证最强的部分是单模型完整轨迹与消融。对 InternVL3-8B、Qwen2.5-VL-7B-Instruct、Gemma-3-27B-it 的 Age 类实验中，从 Seed/Init 到 Align 2，再到 Deep 3，准确率持续下降；尤其 DiggerAgent 带来的下降最大，例如从 Align 2 到 Deep 3 分别下降 37.1/39.5/30.7 个百分点，说明多轮深挖确实能显著暴露静态评测看不到的偏见。

ProposerAgent 的贡献也有消融支撑：去掉 DPO 后，Digger 仍有效，但总降幅明显变小；论文据此证明，Proposer 并非只是“扩数据”，而是在把样本分布推向目标模型漏洞区域。跨模型迁移实验也说明这些 probe 不完全是 source-model-specific：用一个模型上生成的数据去测其他模型，仍能显著压低准确率；但更大模型通常更稳健，如 InternVL3-38B、Qwen2.5-VL-32B 在 transfer setting 下保留更高准确率。

Benchmark 方面，DeepBiasBench 最终有 55,204 个 test instances，并对每类各抽 500 条人工核验，整体通过率 95.2%。表 VI 显示大量模型在 Seed 上接近饱和，但到 DeepBiasBench 明显掉分，这一结论被充分支持。相对不足的是：文中目前主要详细展示了 Age 类完整轨迹，Race/Gender 的单模型分析较少；此外偏见“深度”主要仍通过准确率下降来体现，缺少更细的严重度或一致性量化。

局限与风险

首先，论文把偏见任务严格定义为“证据不足时仍做有害个体判断”，并把 abstention 设为唯一正确答案。这个定义清晰，但适用范围偏窄，更多是在测刻板印象驱动的过度推断，不等于覆盖社会偏见的全部形态。

其次，图像来自 SDXL 渲染而非真实世界采样，尽管作者做了属性控制，但生成图像可能引入风格偏差或新的视觉 shortcut，影响外部生态效度。论文未在此处给出更充分的真实图像验证。

第三，DiggerAgent 的 skill library 带有较强人工设计色彩；虽然实验说明有效，但技能覆盖是否充分、是否会偏向某类语言诱导，论文未明确说明。对真实用户交互分布的贴近程度也有限。

第四，benchmark 构建依赖 5 个 anchor 模型投票，确实有助于共享漏洞提取，但也可能把数据空间拉向这 5 个模型共同的失败模式，对其他模型家族的代表性存在边界。论文有 transfer 结果，但仍不能完全消除此风险。

与我方向的关系

对 VLA / embodied AI 的直接关联不强，因为任务仍是图文问答式偏见评测，而非感知-决策-行动闭环。论文未明确讨论 agent 行动后果或长期交互安全。

但对 embodied AI 与多模态 safety/robustness 很有启发：一是“静态基准不足，必须 response-conditioned probing”的结论几乎可以直接迁移到 embodied 场景中的 instruction following、social compliance、assistive robotics 安全评测；二是其“分布级生成 + 实例级多轮深挖”的框架，可用于构造更难的 multimodal red-teaming 数据；三是它提醒我们，不同模型在静态 benchmark 上的安全排名，到了自适应 probing 下可能重排，这对 VLA 系统上线前评测尤其重要。

VIA: Visual Interface Agent for Robot Control

作者: Hengyuan Hu (Stanford University); Priya Sundaresan (Stanford University); Jensen Gao (Stanford University); Dorsa Sadigh (Stanford University)

方向: VLA | 标签: VLA

简述: 用通用视觉代理零样本控机器人

筛选理由: 思路新颖，免微调控机器人，结果强但接口设定较特殊

Deep Review

一句话判断

这篇论文最值得关注的是：它不把大模型改造成 VLA，而是把机器人控制改写成“通用视觉 agent 操作一个 3D 网页界面”的问题，并在零样本桌面操作上拿到很强结果；如果你关心 VLA 替代路线、agentic control 或 scaling transfer，值得精读。

核心问题与动机

论文要解决的问题是：现有机器人 manipulation 想借助 foundation model，主流做法通常是把 VLM 微调成输出低层动作的 VLA，但这会受限于机器人数据和算力，导致模型规模远小于前沿 FM，进而损失通用视觉理解、物理推理和长程规划能力。作者认为，这正是当前机器人策略在复杂推理和长时程任务上不够强的关键瓶颈。

相对地，Code-as-Policies 虽然不需要端到端动作微调，但依赖人手设计的感知 API 和技能原语，系统上限容易被抽象层设计卡住。本文动机很直接：如果前沿 agent 已经能通过截图、点击、键盘操作软件，那么它是否也能把机器人当成一个“可操作软件”来控制？ 这使问题从“学动作”转成“通过通用界面进行闭环决策”。

方法拆解

VIA 的整体 pipeline 很简单但关键：先把机器人环境做成一个浏览器 3D 控制 UI，其中右侧是由多路 RGB-D 重建的点云场景，左侧是第三人称和腕部相机画面；agent 只能通过 `screenshot` 看这个界面，不能读特权状态，也没有分割、检测等感知 API。输出则不是直接关节动作，而是对一个“蓝色目标夹爪”的 6-DoF waypoint 设置与夹爪开闭，再调用 `execute_waypoint` 让一个简单 PI controller 去执行。

关键模块不是网络结构，而是工具设计 + 闭环 agent loop。工具集很小：移动/旋转/拖拽夹爪、切换开闭、调相机视角、hover 检查点击点、显示旋转 gizmo、执行 waypoint。每次工具调用都会返回更新后的截图，agent 因此可以“看一眼—操作一步—再看一眼”，持续重规划和纠错。训练上几乎没有机器人学习：作者明确使用现成 Claude Code 和 Codex，无机器人专门微调、无额外 policy scaffolding；推理时只给很短的系统提示，任务最小 prompt 仅描述目标和成功条件，详细 prompt 则额外给一份文本形式 waypoint 示例。

创新点含金量

第一，把机器人控制重述为 computer-use agent 问题。它针对的是 VLA 依赖机器人微调、难以直接吃到 frontier FM scaling 的不足。这是实质性问题重构，不只是换壳；可迁移性也强，只要场景能被界面化、任务允许较慢闭环，就可能复用。

第二，使用“人类可操作”的低抽象 3D 界面与 MCP 工具，而非感知/技能原语库。这针对 CaP 受手工抽象限制的问题。这个点更像“方法接口创新”而非算法创新，但含金量不低，因为它把能力瓶颈尽量推回给 FM 本身。对 embodied AI 很可迁移，尤其适合研究“模型原生感知推理能力究竟能否直接落地控制”。

第三，文本 demonstration 可直接提升性能。给 waypoint 列表就能让 CC-Opus 在 3 个 LIBERO-Goal 任务上从 77% 到 100%。这更偏工程发现，但启发很强：机器人任务可能可以从 prompt/反思中学习，而不必先收 teleop 轨迹。是否能系统化扩展，论文还未充分证明。

实验证据

实验在 robosuite 仿真中做了 6 个桌面任务：Stack、Turn on stove、Open drawer、Put bowl on plate、Rainbow、T-block，覆盖抓取放置、 articulated object、精细操作和长程装配。每个配置每任务 10 个 seed。对比主要是不同 agent/model/prompt 组合，而不是和 VLA/CaP 基线做同平台定量比较，这点要注意。

结果上，最小 prompt 下整体成功率从 60%（Codex-5.5）到 88%（CC-Fable）；CC-Fable 在 3 个 LIBERO-Goal 任务上 29/30，汇总为 96.7%；Rainbow 达到 100%。这些结果充分支持一个核心结论：前沿通用 agent 的视觉操作、闭环纠错与规划能力，确实可以零样本迁移到机器人控制，只要接口设计合适。 此外，模型更强通常更好：CC 从 Opus 到 Fable 全面提升，这一点证据较充分。

但有几类结论证据不足。其一，没有与现有 VLA 或 CaP 在相同任务/预算/观测条件下直接比较，因此“比 VLA 更优”目前更多是论证式而非实证式。其二，Rainbow 成功由人工视觉判定，客观性略弱。其三，详细 prompt 对 Codex 无明显帮助，说明“文本 demonstration 普适有效”并未被充分支持。

局限与风险

最大局限是速度和适用边界。作者明确承认依赖 frontier model，推理慢且贵，单成功 episode 常需数美元，不适合动态任务；这意味着它更像 quasi-static、高价值低频任务方案，而不是通用实时控制框架。

第二，实验全部在仿真。论文把真实机器人列为 future work，因此关于感知噪声、标定误差、点云缺失、真实接触不确定性下是否仍成立，论文未明确说明。对机器人论文审稿来说，这是很关键的外部有效性缺口。

第三，控制层较弱。底层只用简单 PI controller，T-block 这类容差约 8mm 的任务成功率仅 10%-40%，说明接口再好也会受执行精度限制。也就是说，VIA 当前更强在高层闭环决策，不代表低层精操已被解决。

第四，评测比较偏“自家设定最适配”的 browser UI 范式。推断：若任务难以通过少量 waypoint 分解、或者需要连续接触调节，VIA 的优势会明显下降。

与我方向的关系

对 VLA 研究，这篇论文最大的启发是：“是否必须学 action head”本身值得重新审视。 VIA 提供了一条旁路：先把高层决策交给 frontier agent，通过界面和工具桥接到执行器，再考虑用它收集数据蒸馏成快策略。这对“慢大脑 + 快身体”的分层 VLA 很有参考价值。

对 embodied AI，这篇论文强调了环境表征和接口设计本身就是能力放大器。相比直接喂原始多相机图像，它把 3D 点云、相机视角控制、可解释工具链组合成 agent 更擅长操作的“工作台”。对多模态 safety/robustness，则启发在于：可把机器人控制拆成显式工具调用与 waypoint 审核流程，更利于插入安全检查、轨迹验证和人类监督；但论文本身未系统研究安全约束、失败恢复上限或越权操作风险。
